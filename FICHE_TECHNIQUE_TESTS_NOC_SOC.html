TEST 2 — Vérifier la Topologie Réseau Mininet & le Port Miroir Open vSwitch (span0)

# 1. Vérifier le switch Open vSwitch s1 et son miroir SPAN

sudo ovs-vsctl list Mirror
ip -br link show span0

# 2. Tester le ping interne depuis l'attaquant h3_atk (10.0.0.99) vers h1_web (10.0.0.10)
H3_PID=$(pgrep -f "mininet:h3_atk" | head -n1)

# 3. Prouver que le port miroir span0 reçoit bien une copie de chaque paquet

✅ Résultat attendu : 0% packet loss et tcpdump -i span0 affiche les requêtes/réponses ICMP entre 10.0.0.99 et 10.0.0.10, prouvant que la duplication matérielle (SPAN) fonctionne.

TEST 6 — Investigation Forensics Réseau en SQL dans ClickHouse

docker exec noc-clickhouse clickhouse-client -q "
SELECT src_ip AS Attaquant, dest_ip AS Cible, dest_port AS Port, proto AS Proto,
       security_status AS Qualification_SOC, count() AS Evenements, sum(bytes_toserver) AS Octets
FROM ntopng.flows WHERE src_ip = '10.0.0.99'
GROUP BY src_ip, dest_ip, dest_port, proto, security_status
ORDER BY Evenements DESC FORMAT PrettyCompact"
✅ Résultat attendu : ClickHouse restitue instantanément le bilan Forensics complet de l'IP attaquante 10.0.0.99 (ports ciblés, protocole L4/L7 et qualification SOC).

TEST 7 — Alerting Grafana & Remédiation Active (Isolation OpenFlow de l'Attaquant)

# 1. Bloquer l'IP attaquante 10.0.0.99 au niveau du switch Open vSwitch s1 (priorité 500)
sudo ovs-ofctl add-flow s1 "priority=500,ip,nw_src=10.0.0.99,actions=drop"

# 2. Vérifier que l'attaquant h3_atk (10.0.0.99) est bloqué à 100%
H3_PID=$(pgrep -f "mininet:h3_atk" | head -n1)
sudo mnexec -a $H3_PID ping -c 2 -W 1 10.0.0.10 || echo "--> ATTAQUANT 10.0.0.99 BLOQUÉ PAR LE SOC !"

# 3. Vérifier que le serveur légitime h2_db (10.0.0.20) communique toujours normalement
H2_PID=$(pgrep -f "mininet:h2_db" | head -n1)
sudo mnexec -a $H2_PID ping -c 2 10.0.0.10

# 4. Lever la quarantaine après le test
sudo ovs-ofctl del-flows s1 "ip,nw_src=10.0.0.99"
✅ Résultat attendu : L'attaquant 10.0.0.99 est totalement isolé (100 % packet loss) tandis que le trafic légitime entre h2_db (10.0.0.20) et h1_web (10.0.0.10) continue sans aucune interruption (0 % packet loss).
